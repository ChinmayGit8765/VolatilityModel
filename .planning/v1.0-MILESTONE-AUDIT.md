## Integration Audit (cross-phase)

The integration checker traced every cross-phase contract (data → features → model → serving → monitoring → dashboard) in code and live against the running compose stack. Two genuine blockers were found — both invisible to per-phase unit tests — and both were fixed and re-verified live:

**BLOCKER 1 (fixed `0984cfd`): the daily flow never generated forecasts.** No automated component called the serving layer, so the prediction log only grew on manual curls and the labeller → performance-monitor → promotion chain was starved (permanent cold-start, `n_champion=0`). Fix: a `forecast_task` in `daily_flow` (features → **forecast** → label) calls `GET {VOLFORECAST_API_URL}/forecast` and fails loudly on error; worker env + depends_on wired in compose. Live re-verified: flow run `7a31611b` COMPLETED with all 6 tasks; prediction log grew +5 rows (one per asset, champion v4) mid-flow.

**BLOCKER 2 (fixed `a77080a`): dashboard drift panel parsed a schema Evidently 0.7.21 never produces.** It searched for `dataset_drift`/`drift_detected` keys that don't exist in the real `metrics: [{metric_name, value:{count, share}}]` output — every render fell back to "unknown", and a tautological unit test masked it. Fix: parser rewritten against the real shape (`dataset_drift = share >= drift_share`, default 0.5 per Evidently; `n_drifted_columns = count`), tests rewritten with exact assertions against a trimmed copy of real output plus a skippable real-file test. Live re-verified on all real drift reports on disk.

**Warnings fixed in the same pass:** drift reference snapshot no longer pinned to stale champion v3 (`855a059` — resolved live from the MLflow alias with highest-version fallback); labeller now imports `PREDICTION_LOG_SCHEMA` instead of duplicating it (`52d22e7`).
